== Line Breaks and Paragraphs

AsciiDoc uses plain text conventions that are easy to read and write.

It's recommended to follow the one-sentence-per-line rule for better version control diffs.

A paragraph is simply one or more lines of text separated by a blank line.
Line breaks within a paragraph are ignored, enabling precise line-by-line editing in source control systems.

Hard line breaks can be inserted using a ` +` (plus sign followed by a space) + 
at the end of a line.

[%hardbreaks]
Hard line breaks can also be applied to all
lines of a block following 
the `[%hardbreaks]` option.

== Text Formatting

You can apply inline text formatting using markup:

* *Bold text* ( `\*bold*` ) or **very bold text** ( `\\**very bold**` ).
* _Italic text_ ( `\_italic_` ) or __very italic text__ ( `\\__very italic__` ).
* `Monospace text` ( `{empty}`monospace`` ) is used for code snippets.
* *_Bold italic_* (`\*\_Bold italic_*`) combinations work.
* Super^script^ and Sub~script~ are possible using `^` and `~`.
* [fuchsia]#This text is fuchsia.# [yellow maroon-background]#Yellow text color on a maroon background.# +
  Standard colors are: aqua, black, blue, fuchsia, gray, green, lime, maroon, navy, olive, purple, red, silver, teal, white, yellow



== Lists

AsciiDoc supports unordered lists, ordered lists, checklists and description lists.

=== Unordered Lists

* An item starting with an asterisk (`*`).
  ** A nested item using two asterisks.
     *** A deeper level.

=== Ordered Lists

In ordered lists you can use different numbering styles using the attribute list before the list items.
[%autowidth, options="header"]
|===
| Attr. Value  | Style                       | Example Output
| [arabic]     | Arabic Numerals (default)   | 1. 2. 3.
| [loweralpha] | Lowercase Letters           | a. b. c.
| [upperalpha] | Uppercase Letters           | A. B. C.
| [lowerroman] | Lowercase Roman Numerals    | i. ii. iii.
| [upperroman] | Uppercase Roman Numerals    | I. II. III.
| [lowergreek] | Lowercase Greek Letters     | α. β. γ.
| [decimal]    | Zero-padded Arabic Numerals | 01. 02. 03.
|=== 

[upperalpha,start=3]

=== Source Code

Source blocks are used for syntax-highlighted code examples.

.A Ruby source code example with callouts
[source,ruby]
----
def hello name = 'World' // <1>
  puts "Hello, #{name}!"  // <2>
end
----
<1> Defines a default value for the name variable.
<2> Prints the greeting to standard output.



## Links & Cross References

External links are automatically rendered if they start with a known protocol (like `http:` or `https:`).
Visit the https://docs.asciidoctor.org/asciidoc/latest/[Asciidoctor Documentation website].
You can use `link:URL[text]` for more control.

https://docs.asciidoctor.org/asciidoc/latest/

Internal cross-references use `<<section-anchor, optional text>>` or `xref:section-anchor[]`.
The `xref` syntax is generally preferred in modern toolchains.
See the discussion on lists in <<Lists>>.
Xref to a specific anchor within the document: anchor:installation-anchor[]
See installation instructions in xref:installation-anchor[].

== Tables

Tables can be created using pipe characters (`|`) with a flexible syntax.

[cols="1,2,3",options="header"]
|===
| Header 1 | Header 2 | Header 3
| Cell A1 | Cell A2 | Cell A3
| Cell B1 | Cell B2 | Cell B3
| Cell C1 | Cell C2 | Cell C3
|===

The stripes attribute in an AsciiDoc table controls the alternating background colors of the table rows (often referred to as "zebra stripping"). The valid values for the stripes attribute are:

[stripes="even"]
|===
| Value | Description

|none   | No striping is applied (default behavior if stripes is not present).
|all    | Every row, including header/footer rows, gets alternating colors.
|odd    | Only odd-numbered data rows are shaded.
|even   | Only even-numbered data rows are shaded.
|hover  | Rows change color when the user hovers their mouse cursor over them (requires support in the Asciidoctor theme/stylesheet).
|===

[options="header"]
|===
| Header 1 | Header 2 | Header 3
2+| This cell spans two columns using the **2+\|** specifier | Normal Text 
| Normal Text | Normal Text
.2+^| centered cell with two rows using the **.2+^\|** specifier
| Normal Text | Normal Text
| Normal Text | Normal Text | Normal Text
2.2+>| test
| Normal Text 
.| Normal Text  
.2+| cell spans two rows using the **.2+** specifier before the pipe.
|===

This table demonstrates various cell merging techniques:

* **Horizontal Merging:** Using a number prefix and the `*` operator (e.g., `2*|`).
* **Vertical Merging:** Using a number prefix and the `+` operator (e.g., `2+<|`).
* **Combined Merging:** Using both operators (e.g., `2.3+^|`).
* **Alignment:** Using operators like `<` (left), `^` (center), `>` (right).

=== KROKI Diagrams

https://kroki.io/[KROKI] offers and creates a large variety of diagrams from textual descriptions. 

In the document attributes a Kroki server must be configured: for example the public `:kroki-server-url: <https://kroki.io>` .
Instead, for privacy reasons, also a local Kroki server can be used. 

Tools that process and render the AsciiDoc must have the Kroki feature enabled (e.g. AsciiDoctor in VSCODE).
